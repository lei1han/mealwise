## 0. 专题目标（30–45 分钟可走完）

1. 对报告 **6 项调优**逐项拍板：做 / 不做 / 延后 / 替代方案。
2. 选定 **实现策略**（一次性合并提示词 vs 分阶段挂载 vs 运营热配置）。
3. 锁定 **首发验收用例**（模拟器 3～5 条 + 单测是否扩 case）。
4. 输出写入本文 **§5 决策记录表**（拍板后由 agent 回写总计划/决策记录）。

### 0.1 与已确认产品决策的关系

| 已决策 | 对本专题的影响 |
|--------|----------------|
| MVP **不含** M5 订阅/定时督促 | **P2 #6（22:00 总结）**、**§6 催报子提示词** 默认 **Out of MVP**，除非你在本专题明确「小程序内被动总结」也要做 |
| MVP **含**资料完善（5B） | 与调优并行，**不占用**本专题 6 项编号；摸底动线 P2 #5 若选「气泡问卷」会与现有 `open_weight_sheet` + `onboarding.profile.submit` 冲突，需单选 |
| 提审 **6C** | 本专题未勾进「首发包」的项，不得作为提审阻塞理由 |

## 2. 横切决策：提示词如何落地？

当前实现：`chat.js` 6 行 `DEFAULT_CHAT_SYSTEM_TEMPLATE` + 记忆块 + 精简 `OUTPUT_CONTRACT`；**未**读 `foods.json` 注入 LLM。成品文档：[deliverables/prompt/2026-08-28-xcoach-prompts.md](../../../deliverables/prompt/2026-08-28-xcoach-prompts.md)。

| 选项 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **S1 合并块（报告 Day1 推荐）** | 把 §2+§4+§9.1（+可选 §9.2）合并进默认 system 字符串；`foods.json` 生成 `food_db_hint` 段 | 改动集中、行为可预期、与单测兼容好 | 单次 prompt 变长、token 成本略升 |
| **S2 动态挂载（文档原设计）** | 按 `onboarding_state` / 关键词 / 上轮 intent 拼接 §3/§5 等子段 | 最贴成品架构 | 开发量最大，需维护挂载表与回归 |
| **S3 运营热配置优先** | 完整版只放在 `app_config.prompt.chat.system`，代码默认仍精简 | 运营可热改 | 无配置时与有配置行为差大（报告已警告）；**不推荐作唯一方案** |

**建议默认组合**：首发 **S1 满足 P0 + 契约 off_topic**；若 P1 子集选「全做」，再 **S2 仅对 §3/§5 做轻量挂载**（profiling 态挂 §3，检测到情绪关键词挂 §5）。

请选：**S1 / S2 / S3 / S1+部分S2**（写在 §5）。

## 3. 六项调优：问题、选项、推荐

### P0 #1 — 食物库 + 拳换算未注入（§4）

**现象**：LLM 缺少 `food:xxx` 表与拳换算规则 → 饮食易全 `food:external` → `is_estimated=true`、热量区间偏差。  
**代码事实**：`foods.json` 51 项已在仓库，`chat.js` 未引用。

| 选项 | 内容 |
|------|------|
| **A 首发必做** | 注入完整 51 项（或报告建议的精简表+id 列表）；含拳换算与「这餐约 min~max」硬格式 |
| **B 折中** | 只注入 Top N（如 24）高频项 + 规则说明，其余仍 external |
| **C 不做** | 维持现状，接受估算偏差（**与产品「热量公信力」风险冲突，不推荐提审前选 C**） |

推荐：**A**。

---

### P0 #2 — 内容安全与禁止身体羞辱（§9.1）

**现象**：精简 system 无毒舌边界词表、无自伤/进食障碍转介 → 合规与投诉风险。

| 选项 | 内容 |
|------|------|
| **A 首发必做** | §9.1 全文进 system（可与 §2 人格合并） |
| **B 最小合规** | 仅「禁止身体羞辱 + 固定拒绝结构」短段，不含完整词表演进 |
| **C 不做** | 依赖模型默认安全（**不推荐**） |

推荐：**A** 或 **B**（资源紧则 B，但需书面接受残留风险）。

---

### P1 打包 — 跑题 / 摸底 / 情绪 / 主模板（§9.2、§3、§5、§2 完整）

报告将多项标 P1；实现可打包决策：

| 选项 | 包含 |
|------|------|
| **P1-Full** | §9.2 off_topic + OUTPUT_CONTRACT 增 `off_topic` intent；profiling 挂 §3；情绪关键词挂 §5；§2 人格完整替换 6 行模板 |
| **P1-Core** | 仅 §9.2 + OUTPUT_CONTRACT 对齐契约 B（off_topic、confidence 口径） |
| **P1-Defer** | 全部延后到首发后（**仅当 P0 已做且你接受体验不稳定**） |

推荐：**P1-Core 最低**；有排期则 **P1-Full**。

---

### P1 #3 — 每日体重：结构化 vs 走聊天 LLM

**现象**：`sheet-weight` mode=weight 调用 `chat.send('今日体重 Xkg')`，偶发 0.1～0.3kg 抽取误差。

| 选项 | 内容 |
|------|------|
| **A 新 action `weight.report`** | payload `{ weight_kg }` 直写 `weight_records` + 确定性教练回复（需回写契约 C） |
| **B 复用 `user.profile.update` 白名单** | 若已有体重字段更新能力，sheet 只调 profile（需确认是否写 weight_records 时序） |
| **C 维持 LLM 抽取** | 零契约改动，接受误差 |

推荐：**A**（与体质 sheet 结构化思路一致）。

---

### P1 #4 — LLM degraded 时数据不丢

**现象**：解析失败时用户消息可能未完整进入业务记忆/补记链路。

| 选项 | 内容 |
|------|------|
| **A 落库 flag + 下轮补记** | 报告方案：存用户原文 + `degraded` 标记，下轮 system 提示教练补记 |
| **B 仅保证 messages 有用户气泡** | 不补记饮食/体重，只避免「对话消失」 |
| **C 不做** | 维持现状 |

推荐：**B 为最低**；追求数据完整选 **A**。

---

### P2 #5 — 摸底减少 sheet 跳转（气泡问卷）

| 选项 | 内容 |
|------|------|
| **A 延后** | 保持 `open_weight_sheet` + `onboarding.profile.submit`（与现契约一致） |
| **B 首发改聊问卷** | 去掉 sheet，纯 LLM+memory 摸底（**大改状态机，与 5B 资料完善并行时风险高**） |

推荐：**A**（已符合决策 1B 外，动线大改不放进首发包）。

---

### P2 #6 — 22:00 一日总结 / §6 催报

| 选项 | 内容 |
|------|------|
| **A 明确 Out of MVP** | 与决策 1B 一致，本专题不讨论实现 |
| **B 仅小程序内被动总结** | 用户晚餐 `chat.send` 后由 LLM 多一句总结，**不**做定时器/订阅 |
| **C 跟 M5 一起做** | 等模板 ID 后 scheduler |

推荐：**A**；若想要闭环感且无推送，可选 **B**（算小功能，需你明确同意「超出纯调优」）。
