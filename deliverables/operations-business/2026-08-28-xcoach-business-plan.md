## 0. 结论摘要（TL;DR）

1. **北极星**锁定"靠谱减重结果"，用两个可观测指标承接：目标体重达成率 + 平均减重达成度。
2. **留存是命门，先于变现**：前 7 天（onboarding 完成定标）是最关键窗口，留存的代理指标是"连续汇报天数"。
3. **成本极低，不是规模化障碍**：平衡档模型下单用户月 LLM 成本约 ¥1，真正的瓶颈是留存与信任，不是钱。
4. **变现必须服务人设**：卖"陪伴的持续与深度"，绝不卖"结果承诺"，付费不破坏"伙伴+教练"信任。
5. **合规红线**：定位为"生活方式陪伴/监督"，不宣称医疗效果、不做疾病诊断，体重/饮食/情绪数据按敏感数据治理。

## 1. 北极星与过程指标拆解 + 数据埋点方案

### 1.1 指标树

北极星源自设计规格 §9：「靠谱减重结果」。拆为 **1 个北极星 + 4 个过程指标 + 2 个负向监控**。

| 层级 | 指标 | 定义 / 计算口径 |
|---|---|---|
| 北极星-1 | 目标体重达成率 | `达成目标体重的用户数` ÷ `完成定标且进入执行期 ≥ N 天（建议 N=28）的用户数` |
| 北极星-2 | 平均减重达成度 | `mean( (initial_weight − current_weight) / (initial_weight − target_weight) )`，仅统计执行期 ≥ N 天用户 |
| 过程-1 | 日均汇报次数 | 当日 `diet_record` + `weight_record` 记录条数 ÷ 当日活跃用户数 |
| 过程-2 | 连续汇报天数（留存代理） | 有任意 diet/weight 记录的自然日连续长度（streak）分布 |
| 过程-3 | 热量汇报覆盖率 | 当日有 `diet_record` 的餐次 ÷ 应报餐次（3 正餐 + 加餐） |
| 过程-4 | 阶段小目标达成数 | 定标后「当日预算达标」的天数计数 |
| 负向-1 | 情绪低谷事件率 | `emotion` 类记忆中含负向/破防语义的记录频次（按活跃用户归一） |
| 负向-2 | 流失节点分布 | 连续漏报天数的分布、最后活跃日起的失联时长分布 |

**口径原则**：所有"过程"指标只在 `goal_stage=执行`（已定标）的用户群上计算，避免把 onboarding 期的低汇报混淆为流失。

### 1.2 指标 → 数据字段映射（对齐设计规格 §7）

| 指标 | 依赖字段 |
|---|---|
| 目标达成率 / 达成度 | `users.initial_weight`、`users.target_weight`、`weight_records.体重`（时序） |
| 日均汇报次数 | `diet_records`、`weight_records`（按日计数） |
| 连续汇报天数 | 上述两表按 `user_id + 日期` 去重后求连续区间 |
| 热量覆盖率 | `diet_records.meal`（breakfast/lunch/dinner/snack）对上应报餐次 |
| 预算达成 | `users.daily_calorie_budget` vs 当日 `diet_records` 汇总热量 |
| 情绪低谷 | `memories.category=emotion` 的 `content` 语义标签 |
| 流失节点 | 各表最新记录时间 vs 当前时间的差值 |

### 1.3 埋点新增字段需求（提给板块 3 后端，待契约 A/C 冻结对账）

设计规格 §7 的 `weight_records` / `diet_records` 只写了「日期」，**不足支撑留存/流失/时序达成度计算**，需后端补充：

- `weight_records`、`diet_records`、`memories`：补精确时间戳 `created_at`（粒度到分钟，用于 streak 与流失）。
- `users`：补 `onboarding_completed_at`（定标完成时刻，作为执行期起点）、`last_active_at`。
- 新增订阅触达日志表：`subscribe_auth`（授权状态 + 模板类型）+ `notify_log`（每次催报的触发类型、送达/点击结果）——这是「主动督促是否有效」的唯一可观测来源。
- `diet_records` 补 `cal_min/cal_max` 已存在；建议加 `confidence` 落库（对齐提示词 §4 的 `confidence`），用于统计"低置信度估算占比"以监控公信力。

> 以上字段为商业侧的埋点诉求，属**对契约 A 的增量提议**，最终以板块 3 冻结 schema 为准。

### 1.4 埋点落地方式

- 采用**后端隐式埋点**（不额外插桩前端）：指标所需数据全部来自 `users / memories / weight_records / diet_records` 四张表 + 订阅触达日志，业务落库即埋点。
- 仅「订阅授权 / 触达点击」需前端上报一次授权结果（见契约 C 订阅授权接口）。

## 2. 冷启动与获客策略

### 2.1 目标人群与切入口径

- **核心画像**：25–45 岁、女性为主、有减肥基础（懂热量、尝试过多次）、屡次反弹、缺的是"被盯着的陪伴"而非知识。
- **切入口径**：不喊"教你减肥"，喊"陪你把这件你早就会的事做完"。卖点是**监督与兜底**，不是方法。

### 2.2 种子用户（0→100）

按"信任浓度"从高到低，分三波：

1. **内圈（10–20 人）**：身边认同"毒舌 + 陪伴"人设的熟人、减肥失败经历者，用于验证对话闭环与催报节奏。
2. **垂直社群（+50 人）**：小红书/微博减肥失败吐槽贴、减肥互助群、贴吧，定向招募"屡减屡败"人群，用「有个教练天天损你但不抛弃你」作为钩子。
3. **内容回流（+100 人）**：把"毒舌点醒"的真实对话截图（脱敏）作为传播内容。

### 2.3 渠道

| 渠道 | 打法 | 优先级 |
|---|---|---|
| 微信生态 | 服务通知 + 朋友圈 + 公众号，搜索「减肥打卡/监督」语义 | 高 |
| 小红书 | 放"毒舌教练"对话截图、减肥复盘帖，挂小程序码 | 高 |
| 口碑/裂变 | 「把你的监督教练分享给一个也减不下来的朋友」 | 中（待产品稳定后） |

### 2.4 口碑传播点（可分享的"钩子"）

- **反差人设**：毒舌但不抛弃，是天然的话题传播点。
- **靠谱结果**：达成度可视化（"80 天，达成目标 70%"）是最强信任背书。
- **低门槛**：不称重、只讲"几拳"，降低分享的心理成本。

## 3. 留存与陪伴策略

### 3.1 第一周留存（最关键窗口）

- onboarding 在 **5–8 轮内完成定标**（对齐提示词 §10.1），越快定标、越快进入"被盯着"的执行态，流失越低。
- **首日承诺**：教练主动发出第一问（冷启动），不冷场；首日给出"今日预算 + 当天可落地动作"，让用户第一晚就"有被管着的感觉"。
- **Day2–7 习惯钩子**：每日早晚固定触达（早问候 + 晚总结），把"向教练汇报"变成 RTT 极短的仪式。

### 3.2 失联挽回

按漏报时长分级：

| 漏报节点 | 动作（话术对齐提示词 §6） |
|---|---|
| 单餐漏报（1–2 小时） | 轻量戳一下："中午吃了吗？" |
| 连续 1 天漏报 | 轻损点醒 + 给台阶："昨天玩失踪，现在补上还能救。" |
| 连续 3 天漏报 | 情绪兜底切换：停止毒舌，关切为主（"最近是不是状态不好？先聊两句"） |
| 连续 7 天失联 | 触达频次降为低频，发一条"随时回来"的召回，不轰炸 |

### 3.3 里程碑庆祝设计（为后续迭代预留，MVP 话术敷设）

- 阶段：定标成功 / 首个 7 天连续汇报 / 每 -3kg / 达成目标。
- 庆祝动作与"毒舌"人设一致：损一句 + 真夸一句 + 一个可执行台阶（如"破 3kg 了，今晚允许你奖励半拳爱吃的"）。
- 数据可视化（体重曲线 × 里程碑标记）属 M2 迭代，MVP 仅以话术表达。

## 4. 变现模式与定价

### 4.1 核心原则：变现不得破坏"伙伴 + 教练"信任

- **卖陪伴的持续与深度，不卖减肥结果**——避免"付费才能瘦"的道德绑架。
- **免费层必须能真正减重**：对话闭环、定标、督促全免费，让口碑先行；付费只解锁"更深陪伴与更顺滑体验"。
- 任何付费权益不得与"教练是否继续盯着你"强绑定（不能让教练"因为没付费就放弃你"，这会直接杀死人设）。

### 4.2 变现阶段假设（M3 启动，MVP 全免费）

| 权益 | 免费层 | 会员/订阅层（假设） |
|---|---|---|
| 对话闭环 / 定标 / 每日督促 | ✅ | ✅（更高频触达） |
| 体重曲线 / 热量汇总可视化 | 基础 | 高级趋势与报告 |
| 里程碑庆祝 / 成就 | 基础 | 定制化庆祝 |
| 深度计划（运动计划、阶段重整） | — | ✅ |
| 触达频次 / 盲盒权益 | 受限 | 提升 |

### 4.3 定价假设（需成本与竞品校准后定）

- 订阅制为主：**¥19–29 / 月** 或 **¥99–149 / 半年**；不做单次买断（陪伴是持续价值）。
- 定价下限由「单用户月成本 ×3 倍毛利」倒推（见 §5），上限由"一个健身教练/减肥营的替代价格"锚定。
- 验证指标：付费转化率、月续费率、付费前后的达成度是否同升（付费若降低达成度即违背 §4.1，需回退）。

## 5. 成本测算（LLM 单轮 / 单用户月度）

### 5.1 关键假设（参数化，需按实际选型替换）

| 参数 | 取值 | 依据 |
|---|---|---|
| 单轮输入 tokens | 2500 | 提示词 + 记忆 + 历史 N=12（对齐提示词 §10） |
| 单轮输出 tokens | 300 | reply_text + 结构化 JSON |
| 单轮合计 | ~2800 tokens | — |
| 用户日活跃轮次 | 8–12（中位 10） | 早 + 3 餐 + 加餐 + 晚总结 + 情绪 + 催报触答 |
| 月活跃天数 | 25 天 | — |

### 5.2 模型档位定价假设（2026 国产主流 API 量级，务必替换为实测价）

| 档位 | 输入 ¥/百万 | 输出 ¥/百万 | 单轮成本 | 单用户月成本 |
|---|---|---|---|---|
| 经济型（轻量/蒸馏） | 0.5 | 1.5 | ≈ ¥0.0018 | ≈ ¥0.45 |
| 平衡型（性价比） | 1 | 4 | ≈ ¥0.0037 | ≈ ¥0.93 |
| 旗舰型（强推理） | 2 | 16 | ≈ ¥0.0098 | ≈ ¥2.45 |

> 计算：单轮 = 2500×输入单价/1e6 + 300×输出单价/1e6；月 = 单轮 × 10 轮 × 25 天。

### 5.3 降本手段（对齐板块 3 §3.4）

- **Prompt 缓存**：系统提示词 + 静态记忆这段上下文高度稳定，命中缓存后输入成本可降 ~50–80%。
- **上下文裁剪**：动态记忆近 7 天、历史 N=12 轮，控制输入长度（提示词 §10 已内置）。
- **分级调用**：日常饮食/情绪汇报走经济/平衡档；定标、阶段重整等"高价值推理"才上旗舰档。
- **催报去重**：漏报催报按策略触发，避免无谓额外调用。

### 5.4 结论

平衡档下单用户月 LLM 成本约 **¥1**，即便全走旗舰档也仅约 ¥2.5。**成本不是规模化障碍**，单用户收费即可覆盖数十倍，核心矛盾始终是"留存与信任"而非"算力钱"。

## 6. 合规与风险

### 6.1 数据隐私（敏感数据治理）

- 体重、饮食、情绪属**敏感个人信息**：最小化采集、加密存储、传输脱敏、提供删除/导出。
- 明确「记忆点」的使用边界：仅用于个性化陪伴，不做跨用户画像转售。
- 隐私政策与用户协议在小程序首次授权前明示。

### 6.2 内容安全

- 毒舌边界已固化为提示词最高优先级（提示词 §9）：禁止身体羞辱、制造身材焦虑，最低限度兜底。
- 商业侧配套：对模型输出做**毒性词二次校验**（后端降级拦截），并留存异常样本回流优化提示词。

### 6.3 广告 / 医疗属性边界（重点红线）

- **定位声明**：本产品是"生活方式陪伴与监督"，**不宣称医疗/治疗效果**，不做疾病诊断，不给出激进减重承诺（对齐提示词 §3 的"保守目标"、§9 的"建议就医"）。
- 禁用话术：「治疗肥胖」「减肥药级效果」「保证瘦 X 斤」。
- 涉及健康风险信号（BMI 偏低、疑似进食障碍、自伤）一律建议就医，不越界。

### 6.4 风险清单

| 风险 | 应对 |
|---|---|
| 订阅消息频次受限，督促效果打折 | MVP 即验证"授权 + 有限频次"能否撑起盯人，若不足改"小程序内催报卡片 + 外链回流" |
| 热量区间公信力不足 | 监控低置信度占比与用户信任反馈；诚实标注"估算" |
| 付费破坏人设 | 见 §4.1 三条红线 + 付费前后达成度对比验证 |
| 未成年用户 | 年龄门槛提示，涉及未成年人不作身体羞辱、不推激进方案（见安全规范） |

## 7. 里程碑与迭代路线图

对齐设计规格 §8，三段式推进，商业化靠后：

| 阶段 | 范围 | 关键看板指标 | 触发下一阶段的条件 |
|---|---|---|---|
| **M1 MVP**（全免费） | 纯对话闭环 + 渐进定标 + 主动督促 + 记忆落库 | 连续汇报天数、热量覆盖率、流失节点 | 留存达到目标基线，北极星口径可算 |
| **M2 数据可视化** | 体重曲线、热量汇总、里程碑庆祝、成就打卡 | 达成度、里程碑完成率 | 仪表数据支撑付费价值主张 |
| **M3 商业化** | 会员/订阅 + 深度服务 | 付费转化率、续费率、付费达成度 | 达成度与付费价协同验证通过 |

**每一阶段上线前过一遍合规清单**（§6），尤其 M2 的"成就/庆祝"与 M3 的"付费"不得触碰医疗承诺与信任红线。
