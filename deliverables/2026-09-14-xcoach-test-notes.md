### 2.1 T1 数据来源核对（代码）

| UI 区域 | 接口 / 逻辑 | 是否走云 |
|---------|-------------|----------|
| 早餐 / 午餐 / 晚餐 / 加餐 | `API.getTodayMeals()` → `diet.today` 未列入 `REAL_ACTIONS`，固定 `Mock.getTodayMeals()`（`mock.js` 生成示例：今日常见早餐 280 + 午餐 400，晚餐/加餐未记为 `--`） | **否（纯 Mock）** |
| 「今日还可吃」大卡 | `chat-main._loadTodayProgress()`：`remaining = total - consumed`；`total` 优先 `budget.today`（已在 `REAL_ACTIONS`），未加载时兜底 **1450**；`consumed` 优先云端 `budget.consumed`，否则用 Mock 四餐 `total_kcal`（今日示例 **680**） | **混合**：预算可来自云，已消耗常与 Mock 餐食绑定 |
| 典型数字 **770** | 1450 − 680 = 770 | 符合 Mock 默认预算 + Mock 今日两餐，**不能代表云端真实记账** |

补充：前端已预留 `diet.today` 云函数调用，但云函数 `api` 路由**尚无** `diet.today` action；即便把 action 加入白名单也需后端先实现。
